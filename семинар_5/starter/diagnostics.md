# Диагностика ошибок

## Ошибка 1: Отсутствие данных в запросе (попытка получить недоступные данные)

**Трасса:**
[step 1] ['get_key_rate', 'get_inflation']
get_inflation({'year': 2026, 'month': 5}) -> {"error": "нет данных ИПЦ на 2026-05"}
[step 2] ['get_inflation']
get_inflation({'year': 2026, 'month': 4}) -> {"error": "нет данных ИПЦ на 2026-04"}
[step 3] ['get_inflation']
get_inflation({'year': 2026, 'month': 3}) -> {"year": 2026, "month": 3, "cpi_yoy": 6.8, "source": "rosstat_csv"}

text

**Тип ошибки:** Инструмент упал (данные не найдены)

**Причина:**
Агент пытается получить данные за май и апрель 2026 года, но в CSV-файле нет данных за эти месяцы. Агент не знает, какие данные доступны, поэтому перебирает месяцы в обратном порядке, пока не находит доступные данные (март 2026).

**Что бы исправить:**
1. Добавить в системный промпт информацию о том, что данные по инфляции доступны до марта 2026 года
2. Улучшить инструмент `get_inflation`, чтобы он возвращал ближайшие доступные данные с указанием даты
3. Добавить мета-информацию о доступном диапазоне данных

## Ошибка 2: Избыточные вызовы инструментов

**Трасса:**
[step 1] ['get_unemployment', 'get_unemployment', 'get_unemployment',
'get_unemployment', 'get_unemployment', 'get_unemployment',
'get_unemployment', 'get_unemployment', 'get_unemployment',
'get_unemployment', 'get_unemployment', 'get_unemployment']
get_unemployment({'year': 2022, 'month': 1}) -> ...
get_unemployment({'year': 2022, 'month': 2}) -> ...
... (все 12 месяцев 2022 года)

text

**Тип ошибки:** Неправильный порядок вызовов / неоптимальное использование

**Причина:**
Агент не знает, что можно получить все данные за год более эффективно, или не умеет анализировать данные без полного перебора. Агент делает 12 отдельных вызовов для поиска пикового значения.

**Что бы исправить:**
1. Добавить инструмент `get_unemployment_range(year_start, year_end)` для получения данных за период
2. Улучшить промпт, чтобы агент понимал, что можно запросить несколько месяцев
3. Научить агента использовать `compare_periods` для поиска экстремумов

## Ошибка 3: Проблемы с кодировкой в логах

**Трасса:**
{"step": 2, "final": "РћС„РёС†РёР°Р»СЊРЅС‹Р№ РєСѓСЂСЃ ...", ...}

text

**Тип ошибки:** Прочее (проблемы с кодировкой)

**Причина:**
В файле `trace.jsonl` русский текст отображается в виде кракозябр (кодировка UTF-8 отображается как Windows-1251). Это происходит из-за того, что терминал Windows по умолчанию использует кодировку CP866 или Windows-1251.

**Что бы исправить:**
1. Установить кодировку терминала: `chcp 65001` (переключить на UTF-8)
2. В коде явно указывать `encoding="utf-8"` при записи файлов (уже сделано)
3. Использовать PowerShell с поддержкой UTF-8
