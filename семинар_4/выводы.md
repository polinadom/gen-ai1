## RAG-пайплайн

### Архитектура
- **Эмбеддер:** `paraphrase-multilingual-MiniLM-L12-v2` (sentence-transformers)
- **Поиск:** Dense (косинусное сходство)
- **Хранилище:** ChromaDB (in-memory)

### Стратегии чанкинга

| Стратегия | Параметры |
|-----------|-----------|
| **A (fixed-size)** | 2000 символов, без перекрытия |
| **B (recursive)** | chunk_size=400, overlap=80, separators=["\n\n", "\n", ". ", " ", ""] |

### Запуск

```bash
# Установка зависимостей
pip install -r requirements.txt

# Запуск evaluation
python src/rag_pipeline.py
```

## Анализ ошибок

### Ошибка Fixed-size (вопрос №7)

**Вопрос:** "Как метод 'отсрочки с увеличивающимся интервалом' помогает не перегружать сервис и связан ли он с 'защитой от лавинных отказов'?"

**Gold:** doc_1 (оба понятия в одном документе)

Как итог:
- Fixed-size чанкинг разбил doc_1 на чанки по 2000 символов
- Понятие "экспоненциальный backoff" оказалось в начале документа
- Понятие "circuit breaker" (защита от лавинных отказов) — через ~3500 символов
- При запросе не получилось найти связь и выдались какие-то неподходящие доки

Причина ошибки:  Большой фиксированный чанк не гарантирует сохранение связи между удалёнными понятиями. Эмбеддинг усредняет семантику всего чанка, и специфические термины "размываются" на фоне другого текста.

### Ошибка Recursive (вопрос №10)

**Вопрос:** "Что общего между 'экспоненциальным ожиданием' при сбоях, 'тремя состояниями защитного выключателя' и 'автономными наблюдателями' в системах с несколькими агентами?"

**Gold:** doc_1 (backoff + circuit breaker) + doc_5 (guardian agents)

- Recursive чанкинг разбил doc_1 на 14 маленьких чанков по 400 символов
- Информация про backoff — в одном чанке
- Информация про circuit breaker — в другом чанке
- При запросе ретривер не смог "собрать" общий смысл doc_1 и выдал `["doc_7", "doc_6", "doc_3"]`

**Почему ошибка:** Слишком маленькие чанки дробят контекст документа. Для поиска по одному документу, где информация разнесена, маленькие чанки не позволяют эмбеддингу увидеть документ целиком.

## Вывод

В ходе лабораторной работы был собран корпус из 7 технических статей (около 55 000 символов), составлена gold-разметка из 12 вопросов (8 из которых — сложные multi-hop), реализован RAG-пайплайн с двумя стратегиями чанкинга.
1. **Обе стратегии показали одинаковую эффективность — 91.67%** (11 из 12 вопросов найдены)
2. **Fixed-size** проигрывает на внутридокументных связях между удалёнными понятиями 
3. **Recursive** проигрывает на обобщении информации из одного документа при слишком маленьких чанках 
4. Стартегии в целом показывали хорошие результаты, и было сложно составить вопросы, на которых возникнут ошибки.
