# Отчёт: анализ отзывов о сервисах доставки еды

## 1. Задача и данные

### Задача

Построить рабочий конвейер, который по корпусу пользовательских отзывов о сервисах доставки еды:

- извлекает структурированные данные (автор, рейтинг, проблемы);
- строит аспектную картину и продуктовую сводку;
- отвечает на ad-hoc вопросы продакта через RAG и агента с инструментами;
- проверяет галлюцинации и качество рекомендаций.

**Зачем:** продакт-команде нужен не разовый пересказ отзывов, а воспроизводимый пайплайн — от сырого корпуса до проверенных рекомендаций с метриками качества.

**Предметная область:** Яндекс Еда, Самокат, Купер — сознательно отличная от семинаров область (там — банковские приложения и фокус-группы).

### Данные

| Параметр | Значение |
|----------|----------|
| Источник | Синтетический корпус `input/reviews_corpus.txt` |
| Объём | 25 отзывов, ~4 200 слов |
| Формат | Блоки `=== REVIEW N ===` с метаданными |
| Сервисы | Яндекс Еда (9), Самокат (8), Купер (8) |
| Платформы | App Store, Google Play, RuStore |

Данные **синтетические** (авторски сгенерированы для проекта), стилистически имитируют реальные отзывы. Это не выдаётся за реальных людей.

Подготовка: ручная разметка формата. Полный LLM-прогон: `python pipeline.py run` (артефакты в `output/`).

## 2. Система

### Техники курса 
| # | Техника | Где | Зачем |
|---|---------|-----|-------|
| 1 | Структурированный IE | `pipeline.py` | Извлечение `Review` с issues и цитатами |
| 2 | `field_validator` | `schema.py` | `rating` 1–5, `review_date` не в будущем |
| 3 | Map-Reduce | `pipeline.py` | Сводка 25 отзывов → headline + action_items |
| 4 | LLM-as-judge | `pipeline.py` | Проверка обоснованности рекомендаций |
| 5 | RAG (BM25) | `rag.py` | Ответы на вопросы по корпусу с цитатами |
| 6 | Агент + инструменты | `agent.py`, `tools.py` | stats, search, compare, calculate |
| 7 | Мультиагент PWC | `orchestrator.py` | Сложные вопросы → подвопросы → критик |

Структурированный вывод: все LLM-вызовы через `llm_client.py` с **`response_model`** (Pydantic) и **`max_retries=3`**.

### Схема пути данных

```
input/reviews_corpus.txt
  → pipeline.py: IE → aspects → Map-Reduce → judge → output/reviews.json, summary.json
  → rag.py: chunk → BM25 → retrieve → RAGAnswer
  → agent.py: ReAct → tools (search/stats/compare/calculate) → trace.jsonl
  → orchestrator.py: planner → workers → critic → synthesize
```

### Проверка галлюцинаций (`hallucination.py`)

- ghost-цитаты в аспектах/issues — подстрока цитаты должна быть в корпусе;
- ghost-цитаты в RAG — цитата должна быть в ретривленном контексте;
- подозрительные числа в ответе агента — числа, отсутствующие в логе инструментов.

**Результат полного прогона:** ghost-цитаты **1/87 (1.1%)**, judge score **0.90**, время пайплайна **70.4 с**.

### 3.2. Статистика по сервисам (из IE)

| Сервис | Отзывов | Средний рейтинг | Топ-жалобы (категории) |
|--------|---------|-----------------|------------------------|

| Купер | 8 | 2.88 | support (3), courier (2), food_quality (2) |

**Вывод по сервисам:** рейтинги Яндекс Еды и Самоката почти равны (~3.1), Купер заметно ниже (2.88). У всех трёх лидируют жалобы на поддержку; у Купера сильнее проблемы с курьерами и качеством еды.

### 3.3. Продуктовая сводка (Map-Reduce)

**Headline:** Сервис страдает от задержек доставки, проблем с качеством еды и неэффективной поддержки, но экспресс-доставка и подписка ценятся.

**Ключевые находки:**

1. Частые задержки: опоздания 40–75 мин, несоответствие заявленному времени (15 мин vs 40 мин).
2. Качество еды: холодные блюда, просроченные продукты, посторонние предметы, помятая упаковка.
3. Поддержка: шаблонные ответы, реакция через сутки, закрытие тикетов без решения, роботы в чате.
4. Цены: рост на 20%, минимальная корзина 900 руб, скрытые комиссии.
5. Приложение: вылеты, зависания, сброс корзины, перегруженность баннерами.
6. Курьеры: грубость, заказы у двери без звонка, проблемы с геолокацией.

**Рекомендации (action_items):**

1. Улучшить прогноз доставки с учётом загрузки склада и погоды.
2. Контроль температуры и упаковки перед выдачей курьеру (пицца, суши).
3. Приоритетная поддержка по качеству еды и просрочке (ответ ≤ 2 ч).
4. Прозрачные комиссии и полная стоимость до заказа.
5. Стабильность приложения на старых Android, меньше баннеров.

## 4. Где пайплайн ошибался

### Пример 1: R1 — «холодная еда» (RAG)

**Вход:** «Кто жаловался на холодную еду?»

**Искажение:** ответ «Никто не жаловался» при **confidence 1.0**, хотя в корпусе: Игорь Н. — «Пицца приехала холодной»; Марина К. — рис комнатной температуры.

**Причина:** BM25 не поднял нужный чанк; генератор уверенно отрицает факт. +1 ghost-quote.

### Пример 2: A4 — верный ответ, неверный путь (агент)

**Вход:** «Больше жалоб на цену — Самокат или Яндекс Еда?»

**Искажение:** ответ верный (Яндекс Еда: 2, Самокат: 1), но tools = `get_service_stats` + `search_reviews` вместо `compare_services(aspect=price)`.

**Причина:** модель нашла ответ обходным путём; eval проверяет путь строго.

### Пример 3: Map-Reduce — потеря противоречий

**Вход:** Самокат хвалят за 15 мин (Алексей П., Светлана Е.) и ругают за 40 мин (Глеб Ш.).

**Искажение:** headline «экспресс-доставка ценится» без акцента на контрпример.

**Причина:** reduce-слой сжимает противоречия; judge 0.90 всё же принял сводку.

### Пример 4: A7 — подозрительное число

**Вход:** «На сколько звёзд выше рейтинг Яндекс Еды чем у Купера?»

**Искажение:** ответ верный (0.23), но `check_number_hallucination` пометила 1 подозрительное число — формат «звёзд» vs сырые float в логе tools.

**Причина:** эвристика сравнивает строки ответа и лога инструментов слишком буквально.

## 5. Выводы

### Ответ на исходную задачу

По 25 отзывам о трёх сервисах доставки главные боли пользователей:

1. **Скорость доставки** — опоздания, несоответствие ETA.
2. **Качество еды** — холодная/просроченная еда, упаковка.
3. **Поддержка** — медленная, шаблонная, слабые компенсации.
4. **Цены и комиссии** — рост, непрозрачность.
5. **Приложение** — баги, перегруженный UI.

Позитив: экспресс-доставка (Самокат), подписки с бесплатной доставкой, удобный трекинг (Яндекс Еда).

По рейтингам: **Самокат 3.12 ≈ Яндекс Еда 3.11 > Купер 2.88**. Разница мала, выборка невелика.

### Границы применимости

- 25 синтетических отзывов — статистика неустойчива, нельзя экстраполировать на NPS.
- BM25 без dense-эмбеддингов слаб на синонимы («холодная еда» vs «комнатной температуры»).
- Judge проверяет наличие жалоб, но не полноту сводки (противоречия теряются).
- Eval pass-rate 88.2% — не 100%; 2 провала осмысленны и разобраны выше.

### Трек B: что в прод, что переделать

| Оставить в прод | Переделать |
|-----------------|------------|
| Pydantic-схема + `field_validator` | Human-in-the-loop на IE |
| ghost-quote check (1.1% поймано) | Fuzzy-match вместо exact substring |
| LLM-as-judge для action_items (0.90) | Калибровка judge на размеченной выборке |
| BM25 RAG для MVP | Dense + hybrid при росте корпуса |
| trace.jsonl для аудита агента | Кэш, rate limits, снижение токенов (A3: 15k) |
| Мультиагент PWC для сложных вопросов | Ограничение числа шагов агента |

### Итоговая оценка системы

| Компонент | Оценка |
|-----------|--------|
| IE + валидация | Отлично (25/25) |
| Map-Reduce + judge | Хорошо (0.90, рекомендации обоснованы) |
| RAG | Удовлетворительно (4/5 eval, провал на R1) |
| Агент | Хорошо (6/7 eval, избыточные шаги на A3/A5) |
| Мультиагент | Хорошо (2/2) |
| Галлюцинации | 1.1% ghost — приемлемо для прототипа |

**Общий вывод:** конвейер пригоден как аналитический прототип для разбора отзывов о доставке еды. Для продакшена нужны больший корпус.
