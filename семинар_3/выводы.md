## Детали

**Пример 1. Отсутствие галлюцинаций.**

Модель не сгенерировала ни одной выдуманной цитаты. Из 4 проверенных через check_quotes все были найдены в исходном тексте. Это хороший результат.

**Пример 2. Проблемы с валидацией данных.**

Из 20 исходных отзывов только 11 прошли Pydantic-валидацию. Остальные 9 были отклонены из-за отсутствия обязательных полей (рейтинга или даты). Проблема в том, что при генерации отзывов через LLM модель иногда пропускает эти поля. Для решения нужно добавить в промпт более строгие требования и примеры.

**Пример 3. Низкая оценка судьи и автоматический повтор.**

При первом прогоне judge оценил рекомендации в 0.00 баллов. Pipeline заметил это (score < 0.7) и автоматически запустил повторный REDUCE с усиленным промптом. Это сработало как задумано в задании.

**Вердикт судьи (из judge_report.json):**

Одна из рекомендаций получила статус "weakly_supported". Причина - жалобы на производительность были, но они носили единичный характер, без массовости. Судья посчитал связь косвенной.

## 3. Что бы изменила в production

**Оставила бы как есть:**

- Pydantic-валидацию с field_validator (проверка даты и severity)
- Проверку ghost-цитат через check_quotes (простой и эффективный метод)
- Температуру 0.0 для детерминированных ответов
- Механизм автоматического повтора REDUCE при низком judge score

**Переделала бы:**

- Промпт для IE: добавить больше few-shot примеров, чтобы повысить процент валидных отзывов (с 55% до 90%+)
- Увеличить max_retries с 3 до 5 для надёжности на больших объёмах

**Добавила бы:**

- Prompt caching (раунд 6) для экономии средств
- Асинхронную обработку для больших объёмов (100+ отзывов)
- Логирование ошибок для отладки проблем с валидацией
